# Release 1.2.0 — design

Three independent features: native staking rates from the networks, price-jump alerts in Telegram, and the yearly
income in the totals banner. Build them in this order (smallest first is fine too; they don't depend on each other,
except that the banner income picks up staking rates automatically once they exist).

## Why

- **Native staking:** wallets (Keplr, Phantom, Leo) show 0% today, so income "now" is understated and every wallet coin
  looks like it should move to an exchange. Native staking is also a real option for coins held on exchanges
  (move TIA from Bybit to Keplr), so the rate is useful for every coin it exists for, not only wallet coins.
- **Price jumps:** small "lottery" positions are held long-term and not watched daily. When one jumps, the user
  wants to know, look at it and decide by the situation (e.g. take part of the profit if the position is in plus).
- **Banner income:** a portfolio-wide "what my coins earn a year now vs at the best rates" next to
  Invested / Value / P/L; the weekly summary already computes it, the page doesn't show it.

## Constraints

- Public repo: no amounts, balances or portfolio composition in code, tests, docs or commits.
- No API keys for data sources (the user rejected paid Staking Rewards). Only public, keyless endpoints.
- No liquid staking, lending or "earn" vaults: **native staking only** (user's decision). Ready stays as it is
  (native STRK / BTC-token delegation with Ready's validator).
- Chrome MV3 worker; new hosts go into `host_permissions` in `wxt.config.ts` (Chrome asks the user once on upgrade —
  mention it in the release notes).
- Texts in the UI and Telegram are English, plain words, no indicator jargon.

## 1. Native staking rates ("Wallet")

### Approach (decided)

A new entry in `EXCHANGES` (`lib/exchanges/wallet/…`), id `wallet`, name **Wallet** (user's choice of name), whose `loadRates()` merges
per-network modules. Everything downstream — rates cache, Earn column, best-rate alerts, promo logic, weekly summary,
income estimate, banner — picks it up because it's just another exchange.

Rejected: one "exchange" per wallet (Keplr, Phantom…) — the rate belongs to the network, not the wallet; SUI/APT
would have no honest wallet name. Rejected: Staking Rewards API — €166+/month, key required.

### Rates

Each rate is `days: 0` with `unbondingDays` = the network's unbonding period (shown as the existing
"flexible, N-day withdrawal" / pill). Sources give network rates before the validator's commission; the module
**subtracts a typical 10% commission** (`rate × 0.9`, one constant) so Wallet compares fairly with exchange rates
everywhere (best rate, alerts, income, banner). Shown with "≈" in the Earn column (tooltip: "network rate after a
typical 10% validator fee; your validator's fee may differ").

Drift of network rates is accepted: Wallet uses the same `minIncrease` alert threshold as exchanges (user's
decision: watch how it behaves, raise it later if it spams).

Stages (each one shippable on its own; stop after any stage if a source misbehaves):

| Stage | Coins | Source (all keyless, checked with curl on 2026-11-13/16) | Unbonding |
|---|---|---|---|
| 1 | TIA, FET, SAGA | `https://chains.cosmos.directory/` (all chains in one ~2 MB request) → `.chain.params.calculated_apr` (fraction) for `celestia`, `fetchhub`, `saga` | 14d / 21d / 21d — read from the chain params if present, else hard-code |
| 2 | SOL | Solana RPC `https://api.mainnet-beta.solana.com`: `getInflationRate.validator` × total supply (`getSupply`) ÷ active stake (sum of `activatedStake` from `getVoteAccounts`) ≈5.3% before the fee on 2026-11-16 | ~2–3 days (one epoch) |
| 3 | APT | `https://api.mainnet.aptoslabs.com/v1/accounts/0x1/resource/0x1::staking_config::StakingRewardsConfig` → `rewards_rate.value / 2^64 × 4380` | up to 14d |
| 4 | SEI, NIBI, SUI | SEI: `total_mint_amount` (`seichain/mint/v1beta1/minter`) ÷ `bonded_tokens` (`cosmos/staking/v1beta1/pool`) via `rest.cosmos.directory/sei`. NIBI: `epoch_mint_provision × 360 × 0.28125 × 0.98 ÷ bonded` via `rest.cosmos.directory/nibiru`. SUI: GraphQL `graphql.mainnet.sui.io`, previous epoch rewards × 365 ÷ total stake | 21d / 21d / ~1d |

Notes from the research (`ROADMAP.md`, "Source research"): use `calculated_apr`, not `estimated_apr`; SEI has fixed
minting, not inflation; NIBI stakers get only 28.125% of inflation; SUI's old JSON-RPC is off; Aptos rate-limits
anonymous requests per IP. Stage 4 formulas are unverified against real rewards — compare against an explorer or
the wallet's own number before shipping each one; drop a coin rather than ship a wrong figure.

Not included: ALEO (hard, later), DYDX (rewards in USDC, noisy — never), group 3 coins (MINA, ROSE…).

**SAGA** (≈55% because little of the supply is staked) is shown and counts like every other rate — the user wants
to see how it behaves. Its tooltip notes why the figure is so high.

All staking rates **count everywhere**: best rate, Telegram alerts, income, weekly summary, banner.

A failing network module must not fail the others: the Wallet exchange returns whatever modules succeeded; only if
all fail does it count as a failed exchange (keeps its last known rates, like any exchange).

### Portfolios bound to Wallet

- The settings page offers **Wallet** in each portfolio's exchange dropdown, like any exchange.
- `guessExchange` maps wallet-like names to `wallet`: Keplr, Phantom, Leo, Solflare, Leap, Petra, Suiet,
  "Sui Wallet", Backpack (case/space-insensitive, as today). Ready stays `ready`. Telegram/Walt stays on the no-rate option.
- The existing no-rate option "Wallet / other" is relabelled **"Other (no rate)"** so it isn't confused with the new
  Wallet entry; its stored value (`none`) doesn't change.
- Effect: TIA in a Keplr portfolio counts as earning the network rate now; no "move TIA out of Keplr" alerts unless
  an exchange beats it. A wallet coin with no staking rate (e.g. a memecoin in Phantom) is 0%, as today.

## 2. Price-jump alerts

### Behaviour (decided)

- Each scheduled check fetches current USD prices for every coin the user holds (positive amount, counted
  portfolios — i.e. not unchecked in the settings). **No minimum position size**: the $10 filter for rate alerts
  does not apply (lottery coins are worth a few dollars).
- If a coin's price is up by **≥ threshold since the previous check**, Telegram gets one message listing those coins.
  Default threshold **30%**, configurable; the feature can be turned off. Defaults: on.
- Baseline = the price saved at the previous check (always updated, alert or not). A coin seen for the first time
  only gets a baseline. Known limitation, accepted by the user: a steady +20% per check never alerts.
- If the previous check was long ago (Chrome was off), the message says how long: "since the last check 2 days ago".
- If a message fails to send, keep the old baselines for the coins in it so the next check retries (same pattern as
  rate alerts' `undo`).

Message (sketch):

```
🚀 Price jump
🪙 XYZ +42% since the last check (6 h ago)
💼 Trash · your position +180%
```

The position line appears only when the cost is known (see below). It is P/L % of the coin across the counted
portfolios: `(current value − cost) / cost`, using the fresh price. Amounts in USD are never shown in this message.

### Data

- **Prices:** `https://api.coinmarketcap.com/data-api/v3/cryptocurrency/quote/latest?id=<ids>&convertId=2781`
  (USD), public, keyless, many ids per request (checked 2026-11-16: returns `data[].quotes[0].price`). New host
  permission `https://api.coinmarketcap.com/*`. Batch ids (e.g. 100 per request).
- **CMC ids:** `fetchPortfolioSnapshot()` already returns `cryptocurrencyId` per symbol; persist symbol → id when
  the content script saves holdings (new storage item or a field on stored holdings).
- **Cost per coin:** when the content script loads the portfolio, also save per coin "net invested" =
  value − P/L (the same definition as the banner). Whether `query-summary` (or another CMC portfolio endpoint the
  page already calls) exposes per-coin P/L must be checked on the live page — **read-only, no transactions**. If it
  isn't available, ship without the position line.
- **Baselines:** new storage item, lower-case symbol → `{ price, at }`.

If the price request fails, skip jump alerts for this check and keep the baselines.

### Settings

Telegram section: "Price jump alerts" checkbox + "from +N% since the last check" number (default 30).

## 3. Yearly income in the totals banner

A fourth stat in the banner:

```
Earn / yr
$123 → $456 at best
3.10% → 5.40%
```

- Left: income a year at current rates; right: if every coin earned its best rate. Same calculation as the weekly
  summary (`estimateIncome` per coin, summed) — the two must agree for the same portfolios.
- Portfolios: the same set as the banner's Invested/Value (CMC-counted, not unchecked in the settings), so the
  percentage is of the Value shown next to it.
- Percent line = income ÷ value of those portfolios.
- CMC hide-balances mode: USD replaced like the other stats; percentages stay.
- Tooltip: the top 3 coins by yearly gain from moving to the best rate ("TIA: Bybit → Wallet, +4.1 pp").
- Rates come from the worker's cache as the Earn column does; positions from the page's portfolio snapshot.
- If rates aren't loaded yet, the stat shows "…" and fills in when they arrive; on failure it's hidden, the rest of
  the banner stays.

## Goals / non-goals / anti-goals

- Goals: honest "now" income for wallet coins; native rates visible for any coin they exist for; a heads-up on
  big jumps; portfolio income at a glance.
- Non-goals: liquid staking, lending, DeFi vaults, validator choice, ALEO, auto-trading, delisting alerts (exchanges
  already email them).
- Anti-goals: wrong rates presented as exact (always "≈" for network rates); alert spam (one message per check,
  jump alerts off-able); anything that needs an API key or leaks amounts into the repo.

## Left to the builder

- Module layout inside `lib/exchanges/wallet/`, the Wallet logo (a neutral icon bundled in `public/`).
- How "≈" is marked on a rate (e.g. an optional `approximate` flag on `Rate`) and rendered.
- Exact settings-page wording and layout.
- Storage item names; batching sizes; request timeouts.
- README and ROADMAP updates; release notes mention the new permission.

## Calls made by the assistant (not discussed in detail)

- **No alert storm on upgrade:** the first check that sees the Wallet exchange records its rates as a silent
  baseline (no "new best rate" alerts for it on that check), like brand-new coins today.
- **Position line source:** store cost per portfolio position when CMC gives P/L per portfolio. If CMC only gives
  P/L for the coin as a whole, show the line only when all of the coin's positions are in counted portfolios;
  otherwise skip it.

- Wallet-like portfolio names map to the Wallet exchange automatically.
- Jump alerts on by default at 30%; one combined message per check.
- Banner tooltip with the top 3 moves.
- Banner income uses the banner's portfolio set (CMC-counted + not unchecked), while the weekly summary keeps its own.
